Every order gets an idempotency key

When you record a sale, BatchCOGS checks the order ID against every previously recorded order before deducting a single unit of material. If the ID already exists, the deduction is blocked — stock does not change, and the block is written to the audit trail.

Try it: record a sale, then submit the exact same order ID again. The second submission returns a "duplicate blocked" result in under a millisecond, with a timestamp pointing to the original.
